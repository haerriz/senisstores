# RizAI neural model design

> Version 5.0.0 · Reviewed 2026-08-26

## Purpose

The bundled neural model improves local language understanding without turning Magento authorization or commerce state into probabilistic decisions. It predicts **intent**, not price, stock, ownership, payment state or order outcome.

## Model artifact

- File: `RizAi/Model/rizai-commerce-intent-v1.json`
- Runtime: `Model/RizAi/NeuralModelRuntime.php`
- Feature encoder: `Model/RizAi/FeatureHasher.php`
- Planner bridge: `Model/Planner/NeuralIntentPlanner.php`
- Training corpus: `RizAi/Training/commerce_intents.jsonl`
- Training script: `RizAi/Training/train.py`

## Architecture

```text
message
  ↓ normalize
word unigrams + word bigrams + character 3/4-grams
  ↓ CRC32 feature hashing
1,024-dimensional L2-normalized vector
  ↓ Linear(1,024 → 96)
ReLU
  ↓ Linear(64 → 19)
Softmax
  ↓
intent + confidence + top-2 margin
```

The model is intentionally small. It is not meant to reproduce the open-ended reasoning breadth of a foundation model. It gives RizAI a genuine learned statistical language component while keeping inference fast, local and auditable.

## Current labels

The model artifact contains the canonical labels, including:

`search_products`, `search_categories`, `get_catalog_navigation`, `get_store_information`, `answer_store_question`, `search_pages`, `get_cart`, `get_wishlist`, `get_recent_orders`, `get_checkout_state`, `get_customer_profile`, `get_newsletter_status`, `product_content`, `compare_products`, `inventory`, `price`, `recommendations`, `smalltalk`, and `out_of_scope`.

## Safety routing contract

The classifier result is never directly executed. `NeuralIntentPlanner` converts only supported predictions into bounded read-only tool proposals. `ToolPolicy` is consulted again, and any tool marked as a mutation or disabled/planner-hidden is rejected.

Sensitive reads still use Magento identity/ownership checks. Product-reference intents such as price or inventory are routed only when server-owned recent-product context exists.

## Confidence controls

Two gates must pass:

- minimum top-1 confidence, default `0.90`;
- minimum probability margin between top-1 and top-2, default `0.18`.

Both are store configurable. The model also never overrides a deterministically locked route.

## Training and model releases

Training is offline and reproducible:

```bash
cd app/code/Haerriz/AgenticCommerce/RizAi/Training
python3 build_dataset.py
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python3 train.py
```

A production retraining process should not deploy a model simply because validation accuracy improved. A candidate should also be tested against:

- untouched real shopper language;
- paraphrases not generated by the same augmentation rules;
- spelling/grammar noise;
- ambiguous and adversarial requests;
- prompt-injection-like catalog/CMS strings;
- every supported locale;
- mutation/negation safety regressions;
- false catalog routing on general questions;
- customer/account authorization boundaries.

## Production MLOps recommendation

A future enterprise model pipeline should be:

```text
sanitized runtime observations
        ↓
human/automated review + label governance
        ↓
versioned training dataset
        ↓
reproducible training
        ↓
offline safety/evaluation suite
        ↓
model artifact + model card + checksum
        ↓
staging shadow/canary evaluation
        ↓
controlled production rollout
```

Do not implement shopper-driven online gradient updates inside a Magento request. Live weight modification would create poisoning, rollback, reproducibility and security problems.

## What would make RizAI an LLM later

The present neural classifier qualifies as a real neural ML model, but not an LLM. A future generative model needs transformer weights trained/fine-tuned for language generation and tool calling. The module already exposes the `rizai_local_llm` provider integration point so those weights can live in an appropriate GPU inference service rather than inside PHP.
